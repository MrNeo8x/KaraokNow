# Bảng công việc MVP KaraokeNow

Cập nhật: 2026-11-26. Đây là nguồn sự thật trong repository về trạng thái triển khai. Quyết định sản phẩm nằm ở `docs/00-product/decision-log.md`; nhật ký từng phiên nằm ở [`work-log.md`](work-log.md).

## Quy trình

Trạng thái (giữ mã tiếng Anh để tìm kiếm):

| Mã | Ý nghĩa | Khi nào dùng |
|---|---|---|
| `DONE` | Hoàn thành | Code, migration, tài liệu API, phân quyền, audit và test tự động bắt buộc đều có; phạm vi task không còn việc gì. |
| `VERIFY` | Chờ nghiệm thu | Code đã merge và test tự động (unit/E2E/smoke) đã qua; chỉ còn kiểm thử trên trình duyệt, kiểm thử FE–BE theo vai trò hoặc UAT. Không còn việc lập trình đã biết. |
| `IN_PROGRESS` | Đang làm | Đang được lập trình thật sự, hoặc code còn nằm trong working tree chưa commit. Giữ số lượng ít. |
| `READY` | Sẵn sàng | Đã đủ rõ và không còn phụ thuộc chưa giải quyết; có thể bắt đầu ngay. |
| `BLOCKED` | Bị chặn | Cần quyết định của PO hoặc điều kiện bên ngoài (tài khoản, môi trường, công cụ) trước khi làm. |
| `BACKLOG` | Tồn đọng | Việc hợp lệ nhưng chưa được ưu tiên hoặc chưa đủ rõ. |

Một task chỉ chuyển `DONE` khi đã có review, build, test liên quan, tài liệu migration/API, kiểm tra phân quyền và audit. Unit test đơn lẻ không đủ cho hành vi database hoặc tranh chấp đồng thời. Task `VERIFY` chuyển `DONE` khi QA-003 (kiểm thử trình duyệt theo vai trò) và phần UAT liên quan (UAT-001) đạt.

Khi còn việc dở trong một task gần xong, **tách việc dở thành task mới** với trạng thái đúng thực tế thay vì giữ task cũ ở `IN_PROGRESS`.

## Tóm tắt hiện trạng

- **Backend** (chạy từ `be/`, Node 26, 2026-11-26): `npm run verify` đạt — build, 21/21 unit suite (73/73 test, gồm kiểm tra env `TRUST_PROXY_HOPS`/rate limit public, chuẩn hoá SĐT, tính cọc và ghi log/ánh xạ lỗi tranh chấp), kiểm tra drift OpenAPI (77 path) và API Markdown. PostgreSQL Docker E2E đạt 60/60 (thêm overtime PD-030, khoá merchant PD-031, quyền theo vai trò API-003, timeout database OPS-004, contract OpenAPI API-004, đối soát tiền mặt PAY-007, IP khách OPS-007), hồi quy tranh chấp giữ phòng (10×100 request và kiểm tra khoá theo phòng tất định): tạo merchant bởi Platform Admin, duyệt listing, check-in/out, hủy/no-show, cọc trên hold và xác nhận khi đủ cọc, lịch booking, catalog công khai, CASH thủ công (idempotency/tổng), phạm vi vai trò/tenant. Migration mới đã kiểm up → down → up. Benchmark QA-002 (`npm run bench:booking`) đạt mọi mục tiêu p95 trên máy local — xem `docs/04-quality/booking-benchmark.md`.
- **Frontend** (`fe/`, session Luồng FE): FE unit test 32/32 (2026-11-26). Smoke test API qua proxy FE (`localhost:3100`, container backend/frontend đã rebuild, migrate + seed UAT) đạt 44/44: trang `/booking`, `/merchant`, `/platform`; PLT-001/002, publication, memberships, audit, backlog, sessions; luồng khách hold → cọc PERCENT → xác minh → xác nhận → check-in/out → tra cứu `COMPLETED`. **Kiểm thử trình duyệt** (Chrome headless qua Playwright, cùng ngày, container đã rebuild): khách mobile 390px và desktop (tìm phòng → báo giá → điều khoản → giữ chỗ → booking code và cọc → tra cứu → reload giữ mã, không cuộn ngang); lễ tân/Owner 19/19 (cọc, xác minh, xác nhận đủ cọc, check-in/out, thu tiền mặt, hủy có hoàn tiền, audit, phiên); Platform và phân quyền 14/14 (tạo merchant, Owner bị chặn `/platform`, Owner tạo Lễ tân → đổi mật khẩu bắt buộc → Lễ tân không thấy màn Owner). Lỗi FE phát hiện và đã sửa xem handoff. Script nằm ở `fe/e2e/`, chạy `npm run e2e` (setup UAT → API smoke → 3 bộ trình duyệt).
- **Chưa có:** kiểm thử screen reader/bàn phím, Safari/Firefox, 429, mất mạng và refresh/logout đồng thời trên trình duyệt; vai trò Branch Manager/Cashier (QA-003), UAT (UAT-001), kết quả CI trên GitHub.

Số lượng theo trạng thái: `IN_PROGRESS` 0, `VERIFY` 40, `READY` 1, `BLOCKED` 8, `BACKLOG` 0, `DONE` 70.
